# 部署指引

本系統有兩種形態，可依用途選擇，兩者共用同一套領域邏輯與檢核規則。

| | 單檔 HTML | 伺服器版 |
|---|---|---|
| 檔案 | `cfo-console.html` | Docker 或 `node dist-server/index.mjs` |
| 使用方式 | 用瀏覽器直接開啟 | 內網網址 + 帳號登入 |
| 資料存放 | 該台電腦的瀏覽器 localStorage | 伺服器資料目錄（可備份） |
| 多人共用 | 否 | 是，含角色權限 |
| 稽核軌跡 | 無 | 有，僅追加不可修改 |
| 適用場景 | 個人試用、教育訓練、外出離線查閱 | 正式導入、內控作業底稿 |

> 內部控制的作業紀錄若要作為稽核證據，請使用伺服器版。單檔版的資料存在使用者自己的瀏覽器裡，無法防止竄改，也沒有稽核軌跡。

---

## 一、單檔 HTML

```bash
npm install
npm run build:html      # 產生 cfo-console.html（約 284 KB）
```

把 `cfo-console.html` 複製到任何地方（共用磁碟、隨身碟、附件）用瀏覽器開啟即可。
沒有任何外部連線需求，資料不會離開該台電腦。

---

## 二、伺服器版（Docker，建議）

### 快速啟動

```bash
cp .env.example .env
# 編輯 .env，至少設定 CFO_ADMIN_USER / CFO_ADMIN_PASSWORD（密碼至少 12 碼）
docker compose up -d --build
```

首次啟動會依環境變數建立管理者帳號並輸出 `✓ 已建立初始管理者`。
建立完成後，建議把 `.env` 裡的 `CFO_ADMIN_PASSWORD` 移除，避免密碼長期留在環境變數中。

預設只綁定 `127.0.0.1:8080`，必須經由反向代理對外提供服務。

### 新增使用者

```bash
docker compose exec cfo node dist-server/index.mjs user:add alice MEMBER 王小明
# 密碼可用環境變數提供，避免留在 shell 歷史紀錄：
docker compose exec -e CFO_NEW_PASSWORD='...' cfo node dist-server/index.mjs user:add bob VIEWER 稽核室
```

角色：

| 角色 | 權限 |
|---|---|
| `ADMIN` | 全部，含公司設定、政策上限、會計年度、重設工作區 |
| `MEMBER` | 執行與勾稽任務、輸入財務數據 |
| `VIEWER` | 唯讀，適合稽核人員與獨立董事 |

## 三、伺服器版（不使用 Docker）

需要 Node.js 20 以上。應用程式**沒有執行期 npm 相依**，建置後只需要 Node 與兩個產出目錄。

```bash
npm ci
npm run build                 # 型別檢查 + 前端 dist/ + 伺服器 dist-server/index.mjs

export CFO_DATA_DIR=/var/lib/cfo
export CFO_STATIC_DIR=/opt/cfo/dist
export CFO_ADMIN_USER=cfo
export CFO_ADMIN_PASSWORD='至少12碼的強密碼'
export CFO_TRUST_PROXY=1
node dist-server/index.mjs
```

### systemd 範例

```ini
[Unit]
Description=CFO 管理系統
After=network.target

[Service]
Type=simple
User=cfo
WorkingDirectory=/opt/cfo
ExecStart=/usr/bin/node /opt/cfo/dist-server/index.mjs
Restart=on-failure
EnvironmentFile=/etc/cfo/env
# 最小權限：僅資料目錄可寫
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/var/lib/cfo

[Install]
WantedBy=multi-user.target
```

## 四、反向代理與 TLS

系統本身**不處理 TLS**，請由反向代理終結，並設定 `CFO_TRUST_PROXY=1`
（cookie 才會帶 `Secure`，且 `X-Forwarded-For` 才會被採信用於稽核軌跡與登入節流）。

Nginx 範例：

```nginx
server {
    listen 443 ssl;
    server_name cfo.example.internal;

    ssl_certificate     /etc/ssl/certs/cfo.crt;
    ssl_certificate_key /etc/ssl/private/cfo.key;

    # 財務系統建議再加一層網段限制
    allow 10.0.0.0/8;
    deny  all;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 五、環境變數

| 變數 | 預設 | 說明 |
|---|---|---|
| `CFO_HOST` | `0.0.0.0` | 監聽位址 |
| `CFO_PORT` | `8080` | 監聽埠 |
| `CFO_DATA_DIR` | `./data` | 資料目錄（需可寫入，備份對象） |
| `CFO_STATIC_DIR` | `./dist` | 前端靜態資源目錄 |
| `CFO_ADMIN_USER` / `CFO_ADMIN_PASSWORD` | — | 首次啟動建立管理者；已有使用者時忽略 |
| `CFO_ADMIN_NAME` | 同帳號 | 管理者顯示名稱 |
| `CFO_TRUST_PROXY` | `0` | 由反向代理終結 TLS 時設為 `1` |
| `CFO_COOKIE_SECURE` | 同 `CFO_TRUST_PROXY` | 是否於 cookie 加上 `Secure` |
| `CFO_SESSION_TTL_HOURS` | `12` | 連線階段有效時數 |
| `CFO_SEED_DEMO` | `0` | `1` 時以示範資料初始化（教育訓練用） |
| `CFO_LOGIN_MAX_ATTEMPTS` | `8` | 登入失敗鎖定門檻 |
| `CFO_LOGIN_WINDOW_MINUTES` | `15` | 鎖定計算時間窗 |

## 六、備份與還原

資料目錄只有三個檔案：

| 檔案 | 內容 |
|---|---|
| `workspace.json` | 公司設定、任務作業紀錄、財務數據、風險登錄簿 |
| `users.json` | 帳號與 scrypt 密碼雜湊（無明文密碼） |
| `audit.log` | 稽核軌跡（JSON Lines，僅追加） |

```bash
# 備份（服務可持續運行：寫入採原子替換，不會取得半寫入的檔案）
tar czf cfo-backup-$(date +%F).tar.gz -C /var/lib/cfo .

# 還原
systemctl stop cfo
tar xzf cfo-backup-2026-08-22.tar.gz -C /var/lib/cfo
systemctl start cfo
```

建議納入公司既有備份輪替，並比照財務系統設定保存年限。
`audit.log` 為 JSON Lines，可直接匯入 SIEM 或提供稽核調閱。

## 七、升級

```bash
git pull
docker compose up -d --build     # 或：npm ci && npm run build && systemctl restart cfo
```

工作區文件帶有 `version` 欄位。若未來的版本改變資料結構，啟動時會將舊檔案更名為
`workspace.json.v1.bak` 保留，再以新結構初始化 —— **不會覆寫既有資料**，
但仍請於升級前備份。

法規更新（新增義務、修改期限、調整檢核門檻）只需更新程式並重新部署：
任務是由義務主檔即時衍生的，既有的作業紀錄以任務 id 對應，不需要資料遷移。

## 八、安全設計與已知限制

已實作：

- 密碼以 **scrypt 加鹽雜湊**儲存，比對使用 `timingSafeEqual`；帳號不存在時仍執行等量運算，避免以回應時間探測帳號
- Session 僅存於記憶體（重啟即失效），cookie 為 `HttpOnly` + `SameSite=Strict`，正式環境加上 `Secure`
- 變更類請求需帶自訂標頭 `X-Requested-With`，跨站表單無法設定，與 `SameSite=Strict` 併用阻斷 CSRF
- 登入失敗依「來源 IP + 帳號」節流並暫時鎖定
- 伺服器**不信任用戶端送來的任何內容**：變更經結構驗證、權限檢查，且勾稽人與作業日一律由伺服器決定
- 靜態檔案路徑穿越防護（含編碼繞過與 NUL 位元組）
- CSP、`X-Frame-Options: DENY`、`nosniff` 等安全標頭
- 容器以非 root 執行、唯讀檔案系統、`no-new-privileges`

尚未實作，導入前請評估：

- **無 TLS**：必須由反向代理提供
- **無密碼自助變更與強制輪替**：目前需由管理者以 CLI 重建帳號
- **無雙因素認證**
- **無使用者管理介面**：新增/停用帳號透過 CLI
- **稽核軌跡為一般檔案**：僅追加且應用程式不提供修改介面，但具備伺服器檔案系統權限者仍可竄改。若需符合更嚴格的內控要求，請將 `audit.log` 即時轉送至集中式日誌系統（WORM 儲存）
- **單一程序**：不支援水平擴充。以本系統的使用規模（單一公司、數十名使用者）而言足夠
