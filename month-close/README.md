# 月結進度追蹤系統

財務部月結步驟的進度追蹤與覆核軌跡系統：一眼看出誰卡在哪裡，並留下不可刪改的覆核紀錄作為內控佐證。

> **目前進度：第 1 階段（核心流程）**
> 已完成：月結範本、一鍵產生當月任務、狀態流程、卡關、等待中、核准／退回、佐證、主管代理／改派／重新開啟、
> 不可刪改的覆核軌跡（含雜湊鏈驗證）、多人同時操作防覆蓋、PIN 登入、假資料與測試。
> 第 2 階段：總覽頁、Excel 月結檢查表匯出。第 3 階段：歷史分析、範本線上編輯。

---

## 資料安全

- 全部在本機（或公司內網）執行，**不呼叫任何外部 API、雲端服務或 CDN**。
- Streamlit 使用統計回傳已關閉（`.streamlit/config.toml` 的 `gatherUsageStats = false`）。
- 預設只接受本機連線（`127.0.0.1`），其他電腦連不進來。
- 真實資料庫與佐證檔放在 `data/`，已列入 `.gitignore`，不會進版控。
- 開發與測試一律使用 `python -m closeapp.demo` 產生的假資料（放在 `data/demo/`）。
- PIN 只存雜湊值；連續輸錯 5 次鎖定 15 分鐘（可在 `config/settings.yaml` 調整）。

## 安裝（第一次，約 3 分鐘）

需要 Python 3.11 以上。Mac 可在「終端機」輸入 `python3 --version` 確認。

```bash
cd month-close
python3 -m venv .venv                # 建立獨立環境，不影響電腦上其他程式
source .venv/bin/activate
pip install -r requirements.txt
```

## 第一次正式使用前要做的事

1. **填人員名單** `config/people.yaml`：姓名、角色（主管／同仁）、分工、初始 PIN（4 位數字，**要加引號**）。
2. **調整月結範本** `config/template.csv`（可用 Excel 開啟，存檔時選「CSV UTF-8」）：負責人、覆核人要填人員名單上的姓名。
3. **核對假日檔** `config/holidays.csv`：已預填 2025、2026 年，請依人事行政總處公告核對。2027 年公告後請補上。
4. 用主管帳號登入 →「月份與系統管理」→ 產生上個月的月結任務。

## 操作說明

### 狀態流程

```
未開始 ──開始──▶ 進行中 ──送出覆核──▶ 待覆核 ──核准──▶ 完成
                   ▲                      │
                   └──────退回（必填原因）─┘
```

- **等待中**：前置步驟還沒全部完成時，「未開始」的步驟會顯示為等待中。可以先按「開始」做準備，但**前置步驟完成前不能送出覆核**。
- **卡關**：任何未完成的狀態都可以標記卡關並填原因；解除時會記錄卡了多久。核准完成時會自動解除。
- **需附佐證**的步驟，沒有有效佐證就不能送出。佐證可以上傳檔案或填共用資料夾路徑；**佐證不能刪除，只能作廢並填原因**。
- **沒有覆核人**的步驟（例如「主管最終覆核」）送出即完成。
- **逾期**：今天已超過預計完成日且尚未完成。

### 誰可以做什麼

| 動作 | 負責人 | 覆核人 | 主管 |
|---|---|---|---|
| 開始、送出覆核 | ✔ | | ✔（代理） |
| 核准、退回 | | ✔ | ✔（代理） |
| 標記／解除卡關、上傳／作廢佐證 | ✔ | ✔ | ✔ |
| 產生月份、改派、重新開啟、取消本月任務、重設 PIN | | | ✔ |

- **職能分離**：同一步驟的負責人與覆核人不能是同一人；負責人（包括主管自己負責的步驟）不能核准自己的工作。
- 主管代為操作時，覆核軌跡會標示「（主管代理）」。
- 改派、重新開啟、取消都必須填原因。

### 截止日規則（template.csv 的「截止規則」欄）

| 寫法 | 意思 |
|---|---|
| `T+3` | 月底後第 3 個工作日（依假日檔，週末與國定假日不算，補班日算） |
| `次月10日` | 下個月 10 日；遇假日順延到下一個工作日 |

「適用月份」欄可填 `全部`、`單月`、`雙月` 或 `3,6,9,12`。營業稅申報設為「雙月」，只出現在 2、4、6…月的月結。

### 實際關帳日

範本中「關帳里程碑」設為「是」的步驟（預設為「主管最終覆核」）完成的日期即為實際關帳日。兩個申報項目不計入。

### 多人同時使用

- 每個人在自己的瀏覽器分頁操作，系統各自獨立處理。
- 如果你看著畫面的期間，別人已經改了同一個任務，你按下去的操作會被**拒絕**，並顯示「此任務已被 ○○ 於 10-02 14:32 更新，請重新整理」。畫面會自動換成最新資料，確認後再操作即可，不會默默蓋掉別人的資料。
- 別人的更新不會即時推到你的畫面，按左側「🔄 重新整理」即可看到最新狀態。

### 覆核軌跡

- 每個動作都會記錄時間、人員、狀態變化與說明，**系統內沒有任何修改或刪除的功能**，資料庫層也有防護。
- 每筆紀錄以雜湊值串接上一筆。主管可在「月份與系統管理 → 軌跡驗證」檢查。如果有人繞過系統直接改了資料庫檔案，驗證會失敗並指出位置。
- 請注意：能直接存取資料庫檔案的人在技術上仍改得動資料，這個機制的作用是**讓竄改一定會被發現**。請限制 `data/` 資料夾的存取權限。

## 資料更新方式

| 要更新什麼 | 改哪裡 | 何時生效 |
|---|---|---|
| 人員、角色、初始 PIN | `config/people.yaml` | 重新整理瀏覽器 |
| 月結步驟、負責人、截止規則 | `config/template.csv` | 下一次「產生月份」；**已產生的月份不受影響** |
| 國定假日、補班日 | `config/holidays.csv` | 下一次「產生月份」 |
| 鎖定次數、時區等參數 | `config/settings.yaml` | 重新整理瀏覽器（「資料夾」需重新啟動） |
| 本月某步驟改派負責人 | 系統內「主管功能 → 改派」 | 立即 |
| 本月某步驟不適用 | 系統內「主管功能 → 取消本月任務」 | 立即 |

假日檔格式（`類型` 填「假日」或「補班」）：

```csv
日期,類型,說明
2027-01-01,假日,元旦
```

設定檔填錯時，系統畫面會直接顯示哪個檔案、哪一列有問題。

### 備份

```bash
python -m closeapp.backup            # 備份到 backups/年月日-時分秒/
```

系統執行中也可以備份。建議每次關帳後備份一次，並把 `backups/` 複製到公司備份位置。

## 搬到公司內網（讓 5 人用瀏覽器同時使用）

1. 在內網那台電腦依「安裝」步驟安裝，把 `config/` 和 `data/` 整個資料夾複製過去。
2. 修改 `.streamlit/config.toml`：`address = "0.0.0.0"`。
3. 那台電腦設定固定 IP，防火牆只開放公司內網連 8501 埠。
4. 同仁用瀏覽器開啟 `http://那台電腦的IP:8501`。
5. `data/` 必須放在那台電腦的**本機硬碟**，不要放在網路磁碟機上。

> 系統沒有 HTTPS，PIN 為簡易登入，請只在公司內網使用，不要開放到網際網路。

## 測試

```bash
pip install -r requirements-dev.txt
python -m pytest                       # 單元測試＋畫面測試（約 15 秒）
python tests/e2e_two_tabs.py           # 瀏覽器實測：兩個分頁不同人員同時操作
```

- `test_demo.py`：模擬完整月份（產生任務 → 推進 → 退回 → 卡關 → 完成），並檢查雜湊鏈完整。
- `test_services.py`：狀態流程、權限、職能分離、佐證、並行衝突、軌跡不可修改、竄改偵測。
- `e2e_two_tabs.py`：開兩個瀏覽器分頁，A（林應收）標記卡關後，B（陳主管）用舊畫面按「開始」會被拒絕，A 的卡關不會被覆蓋；兩人同時操作不同任務都成功。

```
│   ├── audit.py           # 覆核軌跡與雜湊鏈

│   ├── services.py        # 業務規則（狀態流程、覆核、卡關、佐證）

├── start.sh / start_demo.sh
└── requirements.txt
```

## 已知限制（第 1 階段）

- 總覽頁、Excel 匯出、歷史分析尚未提供（第 2、3 階段）。
- 範本目前要直接編輯 `config/template.csv`；線上編輯於第 3 階段提供。
- 檔案上傳元件的按鈕文字（Browse files、Upload）是 Streamlit 內建的英文，無法改成中文。
- 「分析性覆核」第一版只當一般步驟，請上傳差異說明表當佐證，系統不讀試算表數字。
