# CFO 管理系統｜公開發行公司財務長工作台

一套為**台灣公開發行／上市櫃公司財務長**設計的管理系統：把財務長職責拆成九大職能面向，
再把每個面向「定期該做的事」變成有到期日、有負責人、有檢核清單、有法源的可追蹤任務，
並以規則引擎對財務數據執行自動檢核。

```bash
npm install
npm run dev      # 開發模式 http://localhost:5173
npm test         # 執行 79 項單元測試（期限推算、公式引擎、檢核規則、文件一致性）
npm run build    # 產出靜態站台至 dist/
```

前端單頁應用，無後端依賴，資料存於瀏覽器 localStorage。

---

## 一、系統回答的三個問題

| 問題 | 系統模組 |
|---|---|
| 財務長要管哪些面向？每個面向的職責與失效後果是什麼？ | **職能與義務主檔** |
| 這些面向裡，哪些事情要「定期」做？什麼時候到期？誰做？做完要留下什麼？ | **法遵行事曆** + **任務檢核清單** |
| 怎麼知道「有沒有出事」，而不是等到出事才知道？ | **財務檢核**、**公司治理檢核**、**風險登錄簿** |

## 二、九大職能面向

| 面向 | 涵蓋範圍 |
|---|---|
| 財務會計與財報編製 | 月結／季結／年結、合併報表、IFRS、會計師溝通、財報公告申報 |
| 預算、管理會計與績效 | 年度預算、差異分析、滾動預測、資本支出評估與投後追蹤 |
| 資金、外匯與融資 | 現金流量預測、銀行額度、covenant、避險、資金貸與及背書保證 |
| 稅務 | 營業稅、營所稅暫繳／結算、扣繳、未分配盈餘、移轉訂價、有效稅率 |
| 法遵、公司治理與資訊揭露 | 董事會／審計委員會／薪酬委員會、股東會、重大訊息、內部人申報 |
| 內部控制與內部稽核 | 稽核計畫與報告、自行評估、內控聲明書、缺失改善申報 |
| 投資人關係與股務 | 法說會、股利分派與除息、股權結構分析 |
| 風險管理與保險 | 風險登錄簿、壓力測試、信用風險、D&O 等保險統籌 |
| 永續資訊與氣候相關揭露 | 永續報告書、溫室氣體盤查查證、氣候財務影響評估 |

## 三、系統規模

- **9** 個職能面向、**48** 項義務（含 2 項事件驅動）、**266** 個檢核點
- **24** 條財務檢核規則、**83** 個財務指標（47 個輸入科目 + 36 個衍生指標）
- 曆年制公司單一會計年度自動展開約 **215** 筆任務實例
- **79** 項單元測試涵蓋期限推算、公式引擎、規則庫完整性與文件一致性

## 四、核心設計

### 期限推算與營業日調整
義務主檔只描述規則（「期間終了後 45 日」、「期間終了後 3 個月」、「期間內 9/30」），
由 `src/engine/schedule.ts` 依會計年度展開成實際任務並做營業日調整：

- 法定申報期限遇例假日 → **順延**至次一營業日（`adjust: 'NEXT'`）
- 內部作業期限遇例假日 → **提前**至前一營業日（`adjust: 'PREV'`）
- 每項任務同時保留「法定到期日」與「調整後到期日」，介面上會標示是否經過順延
- 支援非曆年制會計年度（`fiscalYearEndMonth`）

### 檢核規則以算式設定，不寫死在程式裡
規則 = 指標算式 + 比較子 + 門檻，門檻本身也可以是算式並引用公司政策參數：

```ts
{
  id: 'RL-01',
  expression: 'endorsementToEquity',
  comparator: '<=',
  threshold: 'policyEndorsementPct',        // 由「設定」頁帶入，改設定即改門檻
  warn: 'policyEndorsementPct * 0.8',       // 黃燈：緩衝不足即預警
}
```

算式由自製解析器（`src/lib/formula.ts`，tokenizer + shunting-yard）求值，
**不使用 `eval`／`Function`**：規則由財會人員維護，必須確保無法執行任意程式碼，且錯誤能被攔截回報。

### 「資料不足」與「檢核未通過」必須分開
缺欄位、分母為零都回傳 `null` 而非 `0`，狀態為 `NO_DATA` 並列出缺漏欄位。
在財務檢核上，把資料不足誤判為通過是最危險的失敗模式。`NO_DATA` 在總分中一樣扣分——
控制無法執行本身就是控制缺失。

### 風險必須對應到控制
風險登錄簿的每一筆都連結到檢核規則與定期義務，並即時顯示所連結規則的現況紅黃燈。
沒有控制對應的風險，等於沒有被管理。

## 五、專案結構

```
src/
├── lib/
│   ├── date.ts            期限推算、國定假日、營業日調整
│   └── formula.ts         安全算式解析／求值器
├── domain/                制度層（可直接維護的主檔）
│   ├── types.ts           型別定義
│   ├── areas.ts           九大職能面向與角色
│   ├── obligations.*.ts   定期義務主檔（法源、期限、檢核清單、權責）
│   ├── metrics.ts         財務指標字典
│   └── rules.ts           檢核規則庫
├── engine/                邏輯層（皆有單元測試）
│   ├── schedule.ts        期程展開與合併
│   ├── checkEngine.ts     指標解算與規則評估
│   ├── directorHolding.ts 董監持股成數法定檢核
│   └── health.ts          任務健康度與緊迫度
├── state/                 狀態與示範資料
├── components/            共用元件與任務抽屜
└── pages/                 七個功能頁
docs/                      設計說明、職能地圖、行事曆總表、檢核規則總表
```

## 六、導入時要調整的地方

| 項目 | 位置 |
|---|---|
| 公司基本資料、板別、實收資本額、政策上限 | 系統「設定」頁 |
| 國定假日（每年須更新） | `src/lib/date.ts` 的 `HOLIDAYS` |
| Covenant 門檻（依實際聯貸合約定義） | `src/domain/rules.ts` 的 `CV-*` |
| 背書保證／資金貸與上限 | 「設定」頁的政策上限，須與董事會通過之作業程序一致 |
| 產業別特殊申報期限（金融保險業等） | `src/domain/obligations.*.ts` |
| 永續報告書期限級距 | `ESG-REPORT` 的 `due`（預設 8 個月，資本額 100 億以上及鋼鐵水泥業為 6 個月） |
